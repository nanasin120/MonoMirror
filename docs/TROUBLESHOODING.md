# TroubleShooting (문제 해결 기록)

MonoMirror 프로젝트를 진행하며 발생한 주요 이슈와 해결 과정 기록

## 1. translation 학습 안됨
- 증상 : 카메라의 이동이 0.1로 고정되어 학습이 되지 않음
- 원인 : 가중치를 0.0으로 초기화 하는 바람에 기울기가 0이 되어 학습이 진행되지 않음
- 해결 : 가중치를 std=1e-5로 초기화
## 2. depth는 그대로인데 loss는 떨어짐
- 증상 : depth는 gap없이 0.999로 고정되어있는데 Loss는 계속해서 떨어짐
- 원인 : 초점거리를 최소로 줄여 강제로 맞춤
- 해결 : torch.tanh(intrinsic_raw) * 100.0 + 200.0를 이용해 200에서 시작해 100 ~ 300사이의 값을 갖게 함
## 3. Minimum_Reprojection_Loss 버그
- 증상 : Minimum_Reprojection_Loss가 제대로 작동을 안함
- 원인 : mask 적용에서 잘못 덮어씌움. [pe_n2c[~mask_p2c.bool()]]
- 해결 : [pe_n2c[~mask_p2c.bool()]]를 pe_n2c[~mask_n2c.bool()]로 수정
## 4. 연산량이 너무 커짐
- 증상 : upsampling과 depthHead로 이어지는 과정에서 연산량이 너무나도 커짐
- 원인 : 수많은 conv2d, skip connection 등이 주요 이유
- 해결 : Instant-NGP에서 영감받은 ImplictDepthHead로 깊이 추정 아키텍처를 교체
## 5. 카메라 외부 파라미터가 똑같이 나옴 [2025-05-24]
- 증상 : prev와 next의 카메라 외부 파라미터가 똑같이 나옴. 이는 서로가 똑같이 이동하고 회전했다는것인데 말이 되지 않음
- 원인 : 데이터 부족으로 추측함
- 해결 : F1, F2만 concat했던것과 달리 서로의 차이 Diff = F1 - F2도 concat에 포함해서 학습
## 6. 투명컵 인식 문제 [2025-05-26]
- 증상 : 투명컵이 잘 안됨. 투명인 부분이 비어있는것 같은 문제가 발생함
- 원인 : 투명컵의 경우 빛 반사, 변형 등의 여러 문제가 있어서 이를 단순 rgb 재투영으로는 처리가 힘듬
- 해결 : rgb 재투영이 아닌 특징을 재투영하기로 결정. 이를 통해 rgb에 구애받지 않는 모델이 됨

### Z값 폭팔
- 원인 : 네트워크의 목표는 3D 포인트 클라우드 이런게 아니라 이미지 투영임. "이전 이미지를 현재로 투영해서 현재 이미지와의 픽셀 차이를 줄인다" 이게 목표임. 픽셀 차이를 없애는 가장 쉬운 방법은 '카메라 안움직임, 세상 모든 물체는 무한대 거리에 정지' 이거임. 카메라가 안움직이고 세상 모든 물체가 저 멀리에 있으면 전부 다 투영을 해도 한 점에 모이니 픽셀 차이가 줄어들음.
- 결과 : 카메라 이동량이 0에 수렴. 깊이 최댓값이 비정상적으로 높아짐. 깊이맵은 평평해지고 입체감이 사라짐.
- 해결 : 이동량 정규화, 최솟값 강제 부여, 이러면 무조건 움직일 수 밖에 없으니 나아질거임.

### 가려짐 영역
- 원인 : 카메라가 이동하면 앞 물체에 가려져 안 보이는 배경이 생김. 이전 프레임과 다음 프레임의 오차를 단순히 평균내버리면, 이 가려진 픽셀에서 발생하는 어마어마한 오차를 모델이 그대로 가져오게됨
- 결과 : 모델은 이 오차를 줄이고자 물체의 경계선이나 배경의 Z값을 비틀고 찢어서 억지로 픽셀을 덮어씌움. 그 결과 이미지가 파도치듯 일그러짐
- 해결 : torch.minimum을 이용해 가려진 영역의 오차를 학습에서 자동으로 배제시켜야함

### 눈속임 비율 맞추기
- 원인 : 단일 카메라 환경에서는 '1m앞의 물체를 보며 0.1m 이동한 시차'와 '10m앞의 물체를 보며 1m이동한 시차'가 동일함. 이동량을 억지로 키워놓으면, 모델은 물체도 억지로 멀리 보내서 비율 (이동량 / 깊이)을 맞춰버림.
- 결과 : 카메라는 많이 움직이는데 물체 깊이는 18밖에서 다가오지 않음
- 해결 : DepthHead의 시차 최솟값 조절해 Z거리의 물리적 상한선 강제 조절.

### 카메라 렌즈 박살
- 원인 : 3D 좌표를 2D화면으로 투영할 때 카메라 내부 파라미터 K가 사용되는데 모델이 이걸 마음대로 학습하면, 오차를 줄이기 위해 깊이나 포즈를 수정하는 대신 렌즈의 화각 자체를 왜곡시켜 픽셀을 억지로 끼워 맞춤
- 결과 : fx와 fy값이 코딩해 둔 하한선 (지금은 150)에 그대로 멈추거나 비정상적으로 팽창. 그 결과 3D공간과 2D픽셀 간의 매칭이 붕괴해 재투영 이미지 박살
- 해결 : K를 그냥 고정시켜버리는게 더 좋을듯 함 차라리, 아님 E와 K를 동시에 학습하지 말던가.
